## 它解决什么问题

打排位的时候队友在群里喊「绕后」，你 Alt+Tab 切出去看一眼，切回来屏幕已经灰了。语音不是每局都能开，也不是每个人都愿意开。文字消息又只能待在另一个窗口里。

GameTalk 把打字这一步搬进游戏画面：按 `Alt+G`，屏幕底部弹出一条输入框，打完回车，输入框消失、焦点还给游戏，队友那边立刻收到消息；他们发来的消息以一层完全透明、鼠标点不到的浮层显示在你的画面上，并响一声提示。整个过程不用切窗口，也不会抢走游戏的按键。

关掉游戏之后，它是一个完整的桌面聊天客户端：多房间群聊、好友私聊、图片、表情包、屏幕共享都在。服务端可以自己搭，消息、成员和媒体都存你自己的 PostgreSQL 里。

安装包 2.4MB，Windows / Linux / macOS 三端都有；游戏模式和屏幕采集目前只在 Windows 上提供。

## 工作方式

```
                       ┌──────────────────────────────────────────┐
   游戏画面上            │  主窗口（聊天）                            │
  ┌──────────────┐      │  快捷输入框（Alt+G）                       │
  │ 消息浮层       │◄────┤  消息浮层（透明、点击穿透）                  │
  │ 透明 · 穿透    │ 实时 │  设置窗口                                 │
  └──────────────┘ 推送 │  屏幕共享观看窗（独立系统窗口）              │
  ┌──────────────┐      └───────────────────┬──────────────────────┘
  │ 快捷输入框     │                          │ HTTPS / WSS
  └──────────────┘                          ▼
                       ┌──────────────────────────────────────────┐
                       │  你的服务器：Fastify + PostgreSQL          │
                       │  消息广播 · 房间/好友 · 信令转发 · 每日备份   │
                       └───────────────────┬──────────────────────┘
                                           │ WebRTC 媒体流
                                    成员之间 P2P 直传，
                                    打洞失败时走自建 TURN 中继
```

消息和成员数据只经过你自己的服务器。屏幕共享的视频流是成员之间直连的，服务器只转发建立连接用的信令，不碰画面。

## 快速开始

### 1. 安装

从 [Releases](https://github.com/aocac/GameTalk/releases/latest) 下载对应平台的安装包：

| 平台 | 文件 |
|---|---|
| Windows | `-x64-setup.exe`（自带全部依赖，推荐） |
| Linux | `.deb` 或 `.AppImage` |
| macOS | `.dmg`（Apple Silicon） |

覆盖安装即可升级，不用先卸载旧版本。

### 2. 连接服务器

第一次打开是登录页。如果你用别人搭好的服务器，点「服务器」那一行填地址（例如 `https://chat.example.com` 或 `http://123.207.234.50:8787`），然后注册账号。地址带不带结尾的 `/` 都行，客户端会自动纠正。

没服务器的话可以点「离线试用」看看界面，但不能收发消息；想自己搭见[自托管服务端](#自托管服务端)。

### 3. 开始用

登录后主界面是空的，点「创建 / 加入房间」。创建房间会得到一个 8 位邀请码，把它发给队友，他们在同一个弹窗里输入邀请码就能进来。房间列表在左侧，点一下切换。

想邀请不在电脑前的人，右键房间可以生成邀请链接：能设有效期和使用次数，随时可以吊销。链接打开的网页上有「加入房间」按钮，装了客户端的直接跳转，没装的可以下载。

## 游戏模式（Windows）

默认快捷键是 `Alt+G`，在设置里可以自己录制组合键（录完立刻生效，旧的键会注销掉）。

按下之后，屏幕底部出现一条输入框，里面会显示当前发送目标（`#房间名` 或 `@好友名`）。点目标可以切换到任意房间或好友，不用回主窗口。输入完按 Enter 发送、Esc 取消；中文输入法组词到一半按 Enter 不会把半截拼音发出去。发送后输入框自动关闭，Windows 焦点交还给之前的前台窗口，游戏不会因为这一下切出去。

队友的消息会以浮层出现在屏幕上。这层浮层背景完全透明（不是半透明黑框），鼠标点击直接穿透到游戏，不会挡住操作。位置有六种预设，也能拖到任意位置；缩放范围 50%–200%，显示时长可调，到时间自动消失。自己在主窗口编辑或撤回消息，浮层里的对应条目会同步更新。设置里有总开关，关掉之后浮层根本不会被创建。

不玩游戏的时候，消息走 Windows 系统通知，三档可选：全部消息、只弹 @我 和私聊、静默。点通知回到窗口会自动跳到对应会话；如果你正在打草稿或编辑消息，它不会打断你。

游戏模式需要两个前提：客户端跑在 Windows 上（用到了 Win32 的全局快捷键和焦点接口），以及游戏用无边框窗口化运行。全屏独占模式会盖住浮层，这种情况换成窗口化即可。Linux 和 macOS 客户端的聊天功能是完整的，只是没有游戏模式。

## 聊天

### 房间

创建房间后你会拿到 8 位邀请码。成员列表显示每个人的在线状态，离线成员也在列表里（灰头像），不是消失。

房主可以移出成员，也可以限时禁言（10 分钟到 30 天，到期自动解除）。被踢的人会立刻从房间里消失，禁言期间发送会被服务端拒绝并提示剩余时间。

所有房间是并行订阅的：你人在 A 房间，B 房间的新消息一样会到，侧栏显示未读数和最新一条预览，切过去就能看。断开重连之后会自动补齐离线期间的消息。

### 消息

消息支持引用、编辑、撤回和转发。

- **引用**：右键消息选「引用」，气泡里会出现一个引用块，显示原消息的作者和内容（原消息被撤回则显示占位）。
- **编辑**：只能编辑自己发的消息，双端同步显示「已编辑」标记。
- **撤回**：发送者本人可以撤回自己的消息；房主可以代撤房间里的任意消息，文案会区分「你撤回了一条消息」「XX 撤回了一条消息」和「房主撤回了 XX 的消息」。
- **转发**：右键选「转发」，可以转到任意房间或好友，转过去的消息带「来自 XX 房间 · 谁」的角标。
- **@提及**：输入 `@` 弹出成员补全，上下键选择、Enter 确认。被提到的人会看到独立的橙色角标。

同一人 5 分钟内连续发送的消息会自动合并成一组（只显示一次头像和昵称），撤回的消息会从分组里正确断开。历史消息按 50 条一页向上翻，每个会话的输入草稿是独立的，切换会话不会串。

单条消息最长 2000 字。发送是乐观的：消息立刻上屏，服务端确认后校正；网络断开期间发的消息会排队，连上后按顺序发出。

### 好友与私聊

好友可以用用户名或 `#8 位短 ID` 添加，对方同意后建立关系。好友列表显示在线状态，双击进入私聊，单击看资料页。

私聊是独立的消息通道，只有双方可见，非好友之间看不到任何历史。删除好友不会删除聊天记录，重新加回来还能看到。私聊里同样支持引用、编辑、撤回、图片和表情。

### 图片与表情

发图有两种方式：点输入框左边的图片按钮选文件，或者直接把图片拖进窗口、粘贴截图。图片会自动压缩到最长边 1920、JPEG 质量 0.85 再上传（GIF 保持原样，不会丢动画），单张上限 5MB，一条消息最多 9 张。发送前可以配上文字，也可以只发图。

点消息里的图片打开灯箱，可以滚轮缩放、拖拽平移、在多张图之间前后翻页、保存到本地。

表情面板有两个来源：个人表情包（每个账号 24 个，存在服务器上，换设备同步）和群共享表情库（房间成员共同上传，全群可用，会显示是谁贡献的）。上传的动图同样保留动画。

## 屏幕共享

房间内点输入框上方的共享按钮，系统会弹出选择器，选整屏或某个窗口，需要的话可以带上系统声音。确认后本房间其他成员会看到一条「正在共享」的提示，点「观看」才建立连接，不会突然被塞一脸画面。

共享开始后，采集窗会收成屏幕右下角的一个小控制条：本地预览、观看人数、实际分辨率和码率、帧率都在上面，画质档位可以随时切换，不用回主窗口就能停止共享。观看端是一个独立的系统窗口，有音量条、静音、全屏和画中画。

上行带宽是 P2P 共享的瓶颈：每多一个观看者就多一路编码。所以客户端会按「总预算 ÷ 观看人数」分摊（总预算默认 12Mbps，可在设置里改），单路有下限保护（约 1.2Mbps，再低画面就没法看了），并根据实测丢包和延迟自动上下调整——网络好时会把分辨率和码率顶上去，网络差时优先保帧率。画质默认是「自动」：按观看人数和上行预算选档（1 人给清晰优先、2–4 人给流畅优先、更多人给省流量），也可以手动锁定某一档。控制条和观看窗都会显示当前实际生效的档位，切换立刻能看到数字变化——带宽充足时各档画面其实一样，差别只在带宽紧张时的取舍。想同时给很多人看，要么调低档位，要么分批看。

网络抖动不会再直接断流：ICE 断开后客户端会自动重启连接（退避重试），采集窗和观看窗的信令也会自动重连，重连期间已经建立的媒体连接保持不动。

画面在成员之间 P2P 直传，服务器只转发信令。这带来一个物理限制：两边都在对称 NAT 后面时，打洞失败就直连不通。解决办法是服务器管理员自建一个 coturn 中继（[部署文档](docs/deployment.md)第 9 节），客户端会自动从服务端领取限时凭据，直连失败时走中继。中继密钥只存在服务端，凭据按用户签发、一小时有效。

画面采集目前只在 Windows（WebView2）上提供，观看端三平台都可以。系统声音的采集取决于系统选择器里的开关，且无法只共享某一个程序的声音——这是 WebView2 的能力边界，不是配置问题。

## 设置项说明

设置是独立窗口，从主界面左下角头像菜单进入。

| 设置项 | 默认值 | 说明 |
|---|---|---|
| 服务器地址 | `http://127.0.0.1:8787` | 登录页也能改，改完需要重新连接 |
| 界面主题 | 跟随系统 | 跟随系统 / 浅色 / 深色 |
| 提示音 | 开 | 收到别人消息时响一声；音量 0–100 可调（默认 70），可试听四种音效 |
| 系统通知 | 仅 @我 与私聊 | 全部消息 / 仅 @我 与私聊 / 静默 |
| 游戏模式 | 开 | 关闭后不再注册全局快捷键 |
| 呼出快捷键 | `Alt+G` | 可录制任意组合键，支持全局 ESC 关闭输入框 |
| 屏幕覆盖 | 开 | 关闭后浮层不会被创建 |
| 覆盖位置 | 左上 | 六种预设，或拖拽自定义 |
| 覆盖缩放 | 100% | 50%–200% |
| 覆盖显示时长 | 6 秒 | 消息在浮层里停留的时间 |
| 网络代理 | 关 | 关 = 跟随系统代理；开 = 走指定的 HTTP 代理（如 `127.0.0.1:7890`） |
| 共享画质 | 自动 | 自动 / 清晰优先 / 流畅优先 / 省流量，共享中也能在控制条上切换 |
| 共享上行预算 | 12 Mbps | 按观看人数分摊，单路有下限；家用宽带上行通常 20–50Mbps |
| 共享时静音提示音 | 开 | 共享系统声音期间静音本应用提示音，避免被采进共享流 |

「关于」页显示当前版本和构建标识。构建标识形如 `build.20260909.0229.a621819`，每次构建都不同，用来区分版本号相同的不同安装包。

## 自托管服务端

服务端是一个 Node 进程加一个 PostgreSQL，用 Docker Compose 跑。客户端连的就是它，数据不出你的机器。

### 部署

需要一台能跑 Docker 的 Linux 服务器，以及一个指向它的域名（用 Caddy 自动签 HTTPS/WSS 证书）。

```bash
git clone https://github.com/aocac/GameTalk
cd GameTalk/docker
bash deploy.sh        # 首次运行会生成 .env，填好域名后再跑一次
```

脚本会自动生成数据库密码和 JWT 密钥、拉起服务、装上每日备份的 systemd timer。跑完后 `https://你的域名/health` 应该返回一段 JSON，把域名填进客户端即可。

不用域名、只想在内网或直连 IP 上跑也可以：把 `docker/docker-compose.yml` 里的 Caddy 服务去掉，把 server 的端口改成 `0.0.0.0:8787`，客户端填 `http://服务器IP:8787`。这种情况下没有 HTTPS，密码和消息是明文传输的，建议只在可信网络里这么用。

### 配置

所有配置通过 `docker/.env` 管理，默认值开箱即用：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `JWT_SECRET` | （生产必填） | 登录令牌签名密钥；生产模式未设置或仍是开发默认值会拒绝启动 |
| `JWT_EXPIRES_IN` | `7d` | 登录令牌有效期 |
| `POSTGRES_PASSWORD` | （deploy.sh 生成） | 数据库密码 |
| `CORS_ORIGIN` | `*` | 允许的跨域来源，逗号分隔 |
| `RATE_LIMIT_MAX` | `300` | REST 全局限流（每 IP 每分钟） |
| `RATE_LIMIT_AUTH_MAX` | `10` | 注册 / 登录限流（每 IP 每分钟） |
| `LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |
| `PORT` / `HOST` | `8787` / `0.0.0.0` | 不用 Docker 裸跑时的监听地址 |
| `TURN_SECRET` | （未设置） | 自建 TURN 中继的共享密钥；设置后 `/api/turn` 为登录用户签发限时凭据 |
| `TURN_URL` | （未设置） | TURN 地址，逗号分隔，如 `turn:IP:3478,turn:IP:3478?transport=tcp` |

服务端环境变量清单见 `server/.env.example`（非 Docker 裸跑时用）。

### 备份与恢复

`deploy.sh` 会装一个 systemd timer，每天 04:30 跑 `pg_dump` 全量备份，带完整性校验，保留 14 天，产物在 `/root/gametalk/backups/`。Windows 管理机可以用仓库里的 `docker/pull-backups-windows.ps1` 定时把备份拉到本地（走 ssh，带 SHA256 校验，本地保留 90 天）。

恢复步骤和异地备份的配置写在[部署文档](docs/deployment.md)第 6 节。

### 升级

```bash
cd /root/gametalk
git pull --ff-only
cd docker && docker compose up -d --build server
```

数据库迁移是纯 SQL 文件，服务启动时自动应用，不需要手动执行。升级前建议先备份（timer 每天都会做，也可以手动跑一次 `docker/backup-db.sh`）。

## 安全与隐私

密码用 argon2 哈希，登录令牌是 JWT（HS256），生产模式强制要求独立密钥。传输走 HTTPS/WSS，REST 接口全部需要鉴权。

防滥用方面：REST 全局限流每 IP 每分钟 300 次，注册登录单独限 10 次；WebSocket 单连接每 5 秒最多 25 条消息，单帧上限 64KB，30 秒心跳、70 秒无响应断开。图片和头像通过 UUID 端点访问，不可枚举；上传会校验文件魔数和大小。TURN 凭据按用户限时签发，密钥不进客户端。

服务器只信任来自内网（回环或私有网段）的 `X-Forwarded-For`，公网客户端伪造的转发头会被忽略，避免绕过限流。

数据都在你自己的数据库里，每日备份保留 14 天。

## 常见问题

**连不上服务器怎么办？**

登录页会显示具体原因。依次检查：服务器地址是否写对（结尾的 `/` 可有可无，客户端会自动纠正）；服务器是否健康，浏览器打开 `https://你的域名/health` 应该返回一段 JSON；如果服务器需要走代理才能访问，在设置里打开代理并填地址。

**游戏里看不到浮层？**

先确认游戏用的是无边框窗口化（全屏独占会盖住浮层）；再看设置里「屏幕覆盖」开关是不是开着的；最后检查快捷键有没有被游戏占用，换一个组合键试试。

**跨网络屏幕共享连不上或者黑屏？**

同网络一般直连就能通。跨网络时如果两边都在对称 NAT 后面，打洞会失败，需要服务器管理员自建 coturn 中继（[部署文档](docs/deployment.md)第 9 节）。没有中继的情况下，同网可用、跨网受限。

**换电脑之后聊天记录还在吗？**

在。消息、成员、图片、表情都存在服务器上，客户端本地只保存登录态和界面偏好。换台电脑登录同一个账号就能看到全部历史。数据库每天自动备份，保留 14 天。

**macOS 和 Linux 能用吗？**

聊天功能完整（有对应平台的安装包），也可以观看别人的屏幕共享。游戏模式（全局快捷键、浮层、焦点恢复）和屏幕采集依赖 Windows API，只在 Windows 客户端提供。

**提示音怎么关小或者换掉？**

设置 → 通知里可以关掉提示音、拖动音量滑块，还能试听四种音效（收到消息 / 被 @ / 发送确认 / 失败）。@我 有单独的音色。

**和微信 / QQ 群比，差在哪？**

它没有朋友圈、红包、文件传输、语音视频通话，也不做多设备消息漫游以外的复杂同步。它解决的是「打游戏时不想切窗口」这一件事，顺带把群聊该有的基础功能做全。

## 限制与已知问题

这些是当前版本确实做不到的事，写在这里以免误会：

- **游戏模式只有 Windows**。它依赖 Win32 的全局快捷键和前台窗口接口；Linux 和 macOS 客户端的聊天功能完整，但没有浮层和快捷键。
- **浮层需要游戏用无边框窗口化运行**。全屏独占模式会把它盖住，这是窗口层级决定的。
- **屏幕采集只有 Windows**（WebView2 提供 `getDisplayMedia`），观看端三平台都可以。
- **对称 NAT 环境下屏幕共享需要 TURN 中继**。这是 WebRTC 的物理限制，不是能靠配置绕过的；自建 coturn 的步骤在部署文档里。
- **无法只共享某一个程序的声音**。系统选择器只能给整屏或窗口的系统声音，WebView2 没有暴露进程级音频采集；开启「共享时静音提示音」可以避免本应用的提示音被对方听到。
- **共享给很多人时上行会吃紧**。媒体流是点对点直传、不经过服务器，代价就是每个观看者各占一路编码；客户端会按预算分摊并自适应，但人数多、网络差时画面仍会降清晰度或掉帧。
- **共享画面时系统会显示一条采集提示条**。这是 WebView2 的隐私强制行为，没有官方开关；客户端会尝试用 Win32 接口隐藏它，但系统更新后可能失效。
- **媒体文件没有自动清理**。上传的图片会一直留在数据库里，服务器磁盘需要自己留意。
- **单机架构**。房间和连接状态在内存里，没有引入 Redis，所以不能多实例水平扩展；个人自用和几十人的小队规模足够。

## 本地开发

需要 Node 22、Rust（含 MSVC 工具链，Windows 上还要 Windows SDK 和 WebView2 运行时）。

```bash
# 服务端：默认用 PGlite（零依赖的 WASM PostgreSQL），数据落在 server/data/
cd server && npm install && npm run dev

# 客户端：Tauri 桌面应用，会自己起 Vite
cd client && npm install && npm run tauri dev

# 测试与检查（两个目录各自执行）
npm test && npm run lint && npm run typecheck
```

测试基线：服务端 90 例（PGlite 内存库 + 真实 WebSocket 集成），客户端 37 例（含屏幕共享连接生命周期、自动档位与码率分摊的单元测试）。仓库里另有 13 个双账号浏览器回归脚本（`dev/e2e-*.mjs`），覆盖私聊、编辑、表情、通知跳转、邀请链接、屏幕共享等流程；其中 `e2e-screen-share-media.mjs` 用合成采集流跑真实的 P2P 媒体链路（断言画面推进与音频 RMS），不需要人工点选择器。

数据库结构由 16 个纯 SQL 迁移文件定义（`server/migrations/`），启动时按序自动应用。开发用的 PGlite 和生产 PostgreSQL 执行的是同一份 SQL。

每次 `npm run build` 会生成一个构建标识（`build.<时间戳>.<git 短 sha>`），显示在客户端「关于」页，也写进安装包文件名，用来区分版本号相同的不同构建。
